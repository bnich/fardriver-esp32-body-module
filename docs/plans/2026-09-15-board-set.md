## Format facts already established (do not re-derive)

Read directly from the official spec, not inferred:

| Fact | Source |
|---|---|
| v2 files are **line-oriented, one JSON array per line** | `fmt2 general/conventions.md` |
| File header `["DOCTYPE","SCH","1.0"]`, then `["HEAD",{"editorVersion":...,"importFlag":0}]` | `fmt2 general/file-header.md` |
| ⚠️ **Units are `0.01 inch`** — 1 unit = 0.254 mm | `fmt2 general/conventions.md` |
| Rotation **counter-clockwise positive, degrees** | same |
| Colors `"#RRGGBB"`, `""` = transparent. Booleans `1`/`0` | same |
| `COMPONENT` binds a Device by UUID; `ATTR` overrides Device/Symbol/Footprint/Designator | `fmt2 schematic/component.md` |
| ⛔ **The real `.eprj3` example instead uses JSON OBJECTS with `\|` separators** | `eprj3/example/.../P1.esch2` |

⛔ **That last row is the open question and Task 1 exists to settle it empirically.** Nothing downstream may assume an answer.

⚠️ **Rounding policy:** 42 mm = 165.354 units, 186 mm = 732.283 units. All geometry is computed in mm as `float` and converted once, at emit time, by `mm_to_units()`. Never store units in the netlist.

```python
# tools/eprj3/units.py
"""mm <-> EasyEDA Pro's native unit.

fmt2 general/conventions.md: "all coordinates, lengths, and sizes use
0.01 inch as the unit". So 1 unit = 0.254 mm and 1 inch = 100 units.

Geometry is carried in mm as float everywhere in this project and converted
exactly once, here, at emit time. Never store native units in the netlist --
a number whose unit you have to remember is a number you will get wrong.
"""
MM_PER_UNIT = 0.254

def mm_to_units(mm: float) -> float:
    return mm / MM_PER_UNIT

def units_to_mm(units: float) -> float:
    return units * MM_PER_UNIT
```

```python
# tools/eprj3/records.py
"""THE ENCODING BOUNDARY.

Two encodings are documented by EasyEDA and they disagree:

  ARRAY  -- fmt2 general/conventions.md: "The file is line-oriented; each
            line is a valid JSON array". Header ["DOCTYPE","SCH","1.0"].
  OBJECT -- what the real eprj3 example project actually contains:
            {"type":"DOCHEAD"}||{...}|  -- objects, pipe-separated.

Which one a current editor accepts is UNKNOWN until Task 1's gauge is
opened by a human. Everything else in this package goes through
serialize_record(), so settling it changes exactly this file.
"""
import json

ARRAY = "array"
OBJECT = "object"

#: Set by Task 1 from the gauge result. None = not yet settled.
ENCODING = None

def _compact(obj) -> str:
    return json.dumps(obj, separators=(",", ":"), ensure_ascii=False)

def serialize_record(record, encoding=None, payload=None) -> str:
    enc = encoding or ENCODING
    if enc is None:
        raise RuntimeError(
            "Record encoding not settled. Run Task 1's gauge and set "
            "records.ENCODING before emitting a real project."
        )
    if enc == ARRAY:
        return _compact(record)
    if enc == OBJECT:
        return f"{_compact(record)}||{_compact(payload or {})}|"
    raise ValueError(f"unknown encoding {enc!r}")
```
